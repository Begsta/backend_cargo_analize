# Проверка лабораторной № 3

Основание: раздел «Лабораторная 3» приложенного README (9).md.
Тема: расчёт производительности башенного крана; текущий сервис хранит грузы с массой и объёмом.

## Оценка

Основная программная часть реализована. Полную готовность к защите подтвердить нельзя: интеграционные запросы с PostgreSQL и MinIO в этой среде не выполнены, Docker недоступен.

## Исправления

Лента теперь выбирает одну опубликованную запись через ORDER BY и LIMIT 1, включая переход после последней записи на первую. Масса и объём больше не обрезаются до целого: добавлена миграция 002. API отклоняет отрицательные и бесконечные измерения. Серверные страницы преобразуют новые имена файлов в публичные URL MinIO, страница черновика сохраняет его собственные медиа.

## Соответствие теме

В методичке для лабораторной 3 требуется заявочный веб-сервис, а не отдельный инженерный расчёт. Поэтому не следует добавлять произвольную формулу крана ради названия темы. В текущем проекте нет времени рабочего цикла, параметров крана, коэффициентов использования и результата производительности; масса и объём сами по себе не определяют производительность. Если индивидуальное задание требует расчёт уже здесь, необходим текст задания с исходными данными, формулой и единицами результата. Тогда нужны соответствующие поля, вычисление на сервере и описание в API. Это остаётся открытым пунктом.

FastAPI и SQLAlchemy уже используются проектом. Методичка требует согласования альтернативного стека с лектором; наличие такого согласования по файлам установить нельзя.

## Порядок проверки и защиты

1. Запустить окружение по README, выполнить alembic upgrade head. Не сбрасывать существующую базу.
2. Импортировать коллекцию Postman. Если у пользователя уже есть черновик, сначала опубликовать или удалить его; выбрать реальные файлы image и video для POST.
3. Выполнить запросы коллекции по порядку. Проверить также снятие лайка interest=0, повторную публикацию (409), обращение к удалённому грузу (404), попытку изменения чужого груза (403), передачу creator_user_id при создании (422), дробную массу 3.5 без округления.
4. Сделать скриншоты 1–10 запросов по методичке; дополнительно показать деавторизацию. Логин для повторной регистрации менять, чтобы не получить ожидаемый 409.
5. Для скриншотов 11–13 выполнить три SELECT из README: грузы, отметки, пользователи. Проверить статус deleted и имена файлов в БД, наличие объектов в MinIO.
6. Для 14–15 показать models и api/serializers.py; для 16–17 — singleton, его вызовы и README.
7. Открыть lab3-classes.drawio в draw.io. Четвёртая страница регистрации показана как проектируемая: фронтенд регистрации в лабораторной 3 не реализован, API регистрации есть.
8. Вставить настоящие скриншоты в Word с номерами и подписями; приложить диаграмму, ответы на контрольные вопросы из README, конспекты лекций и исправления прошлых лабораторных.

Полный прогон с БД и MinIO нужен до сдачи; локальные проверки не заменяют его.
